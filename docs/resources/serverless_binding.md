# masterdaweb_serverless_binding (Resource)

Gives a service a bucket or a database as environment variables, with a credential of its own (never the owner's). Binding and unbinding start a deployment (binding unless deploy is false). Any change replaces the binding: the service gets a new credential.

The variables follow the layout (`env_profile`):

| Layout | Bucket | PostgreSQL | MySQL, MariaDB | Redis |
| --- | --- | --- | --- | --- |
| `url` | | `DATABASE_URL` (default) | `DATABASE_URL` (default) | `REDIS_URL` (default) |
| `framework` | `AWS_*` | `DB_*` (Laravel) | `DB_*` (Laravel) | `REDIS_*` |
| `libpq` | | `PGHOST`, `PGUSER`… | | |
| `prefixed` | `MW_STORAGE_*` (default) | `PG_*` | `MYSQL_*` | `REDIS_*` |
| `dotnet` | | `ConnectionStrings__DefaultConnection` (Npgsql) | `ConnectionStrings__DefaultConnection` (MySqlConnector) | `ConnectionStrings__Redis` |

`env_prefix` changes the prefix of the `prefixed` layout, adds one to `url` (`ANALYTICS_DATABASE_URL`), and
with `dotnet` names the connection string (`SHOP_DB_` is `ConnectionStrings__ShopDb`). A binding is refused
when its variables would replace ones the service already has. Its credential is rotated every 90 days with
a deployment; unbinding revokes it an hour later.

## Example Usage

```terraform
# The database as ConnectionStrings__DefaultConnection, in Npgsql's format.
resource "masterdaweb_serverless_binding" "db" {
  service_id    = masterdaweb_serverless_service.web.id
  resource_kind = "POSTGRES"
  resource_name = masterdaweb_database.db.name
  env_profile   = "dotnet"
}

# The bucket as MW_STORAGE_ENDPOINT, MW_STORAGE_BUCKET, MW_STORAGE_ACCESS_KEY_ID…
resource "masterdaweb_serverless_binding" "files" {
  service_id    = masterdaweb_serverless_service.web.id
  resource_kind = "BUCKET"
  resource_name = masterdaweb_object_storage_bucket.files.name
  env_profile   = "prefixed"
  env_prefix    = "MW_STORAGE_"
  access        = "read_write"
}

# Redis as REDIS_URL.
resource "masterdaweb_serverless_binding" "cache" {
  service_id    = masterdaweb_serverless_service.web.id
  resource_kind = "REDIS"
  resource_name = masterdaweb_database.cache.name
}
```

## Schema

### Required

- `resource_kind` (String) BUCKET, POSTGRES, MYSQL (a MySQL or MariaDB database) or REDIS.
- `resource_name` (String) The bucket's or the database's name.
- `service_id` (String) The service that gets the variables.

### Optional

- `access` (String) Buckets: read_write (the default) or read_only. A database binding always has the owner's rights (read_write).
- `deploy` (Boolean) Whether binding starts a deployment that gives the service the variables. False saves it for the next deployment. Unbinding always starts one.
- `env_prefix` (String) The variables' prefix: capitals, digits and underscores, ending in an underscore, like `MW_STORAGE_` (the `prefixed` layout's default for buckets). With `dotnet` it names the connection string (`SHOP_DB_` is `ShopDb`; none is `DefaultConnection`, or `Redis` for Redis).
- `env_profile` (String) The variables' layout. Buckets: `prefixed` (the default) or `framework` (`AWS_*`). PostgreSQL: `url` (`DATABASE_URL`, the default), `framework` (`DB_*`), `libpq` (`PG*`), `prefixed` or `dotnet` (`ConnectionStrings__<name>`). MySQL, MariaDB and Redis: `url`, `framework`, `prefixed` or `dotnet`.

### Read-Only

- `created_at` (String) When the binding was made (RFC 3339).
- `id` (String) The binding's id.
- `resource_id` (String) The bucket's or the database's id.
- `variables` (List of String) The names of the variables the binding gives the service (never their values).

## Import

A binding is imported as `<service_id>/<binding_id>`, or `<service_id>/<bucket or database name>`:

```shell
# As <service_id>/<binding_id>, or <service_id>/<bucket or database name>.
terraform import masterdaweb_serverless_binding.db 0193f0e2-9a4b-7c2d-8e1f-3a5b6c7d8e9f/shop-db
```
