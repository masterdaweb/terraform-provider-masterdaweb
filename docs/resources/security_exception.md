# masterdaweb_security_exception (Resource)

A risk the account accepts in the Security Center: one finding, a check (everywhere or on one instance) or a port, with a justification kept for the audit and an end date. Its findings stop lowering the security score until it lapses. An exception cannot be changed: changing anything replaces it, and destroying it revokes it (its findings count again at once). Once it lapses or is revoked in the console it leaves the state, and the next plan proposes it again — with a later expires_at, to renew it.

The findings to accept come from [`masterdaweb_security_findings`](../data-sources/security_findings): a
finding's `id` for scope `finding`, its `rule_id` for scope `rule`. Accepting a risk takes `security:write`.

## When it ends

The platform caps how long a risk can be accepted (per check, and overall): `effective_expires_at` is the date
that applies, and Terraform warns when it is earlier than `expires_at`. Once the exception lapses — or someone
revokes it in the console — it no longer stands: it leaves the state, as a resource deleted outside Terraform
does, and the next plan proposes it again. With `expires_at` still in the future that accepts the risk anew; with
a date already past the API refuses it, which is the cue to review it and set a later date.

## Example Usage

```terraform
# One finding: the replica's MySQL port, open on purpose to a vendor.
data "masterdaweb_security_findings" "mysql" {
  instance_id = "4123"
  search      = "mysql"
}

resource "masterdaweb_security_exception" "replica" {
  scope         = "finding"
  finding_id    = data.masterdaweb_security_findings.mysql.findings[0].id
  justification = "Read replica reachable only by the analytics vendor's fixed address (ticket OPS-412)."
  expires_at    = "2026-12-31T23:59:59Z"
}

# A port everywhere: a VPN's UDP port is meant to be open.
resource "masterdaweb_security_exception" "wireguard" {
  scope         = "port"
  port          = 51820
  protocol      = "udp"
  justification = "WireGuard listens here on every VPN gateway; reviewed by the security team."
  expires_at    = "2027-03-31T00:00:00Z"
}
```

## Schema

### Required

- `expires_at` (String) When it lapses, an RFC 3339 date-time in the future. The platform caps how long an exception lasts: effective_expires_at is the date that applies.
- `justification` (String) Why the risk is accepted, 30 to 2000 characters, kept for the audit.
- `scope` (String) finding (one finding, finding_id), rule (a check, rule_id, everywhere or on instance_id) or port (port and protocol, everywhere or on instance_id).

### Optional

- `finding_id` (String) With scope finding: the finding (masterdaweb_security_findings). An import takes it from the API (the configuration's, from an API that does not show it).
- `instance_id` (String) With scope rule or port: only on this instance; everywhere when left out. With scope finding, the instance the finding is about.
- `port` (Number) With scope port: the port, 1 to 65535.
- `protocol` (String) With scope port: tcp or udp; both when left out.
- `rule_id` (String) With scope rule: the check's id (a finding's rule_id).

### Read-Only

- `effective_expires_at` (String) When it lapses: expires_at, or the platform's maximum when that comes first (RFC 3339).
- `id` (String) The exception's id.
- `resource_id` (String) With scope finding, that resource's id.
- `resource_type` (String) With scope finding, the kind of resource the finding is about when it is not an instance: serverless_service, database, bucket, storage_key or account.
- `starts_at` (String) When it came into force (RFC 3339).
- `status` (String) active while it is in force.

## Import

An exception in force is imported by its id:

```shell
# By id, while it is in force.
terraform import masterdaweb_security_exception.replica 0193f0e2-8c1d-7a7e-9b1e-2f6a4c0d9e11
```
