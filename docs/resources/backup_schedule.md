# masterdaweb_backup_schedule (Resource)

When an instance is backed up, on the days and at the time given. The instance needs the backup add-on (its addons, like backup-slot), whose slots keep the backups. An instance has one schedule; destroying it stops the scheduled backups and keeps the ones made.

The instance needs the backup add-on (`addons` on `masterdaweb_instance`, like `{ code = "backup-slot", quantity = 3 }`):
without it the API refuses the schedule, saying so. When the slots are full, the oldest backup makes room for the new
one. Restoring a backup is done in the console or with the API (`POST /v1/backups/{id}/restore`): it overwrites the
instance.

## Example Usage

```terraform
resource "masterdaweb_instance" "db" {
  name            = "db-1"
  region_id       = "3"
  plan            = "c4m8"
  image           = "debian-12"
  subscription_id = var.subscription_id
  payment         = "balance"

  # Backups need the backup add-on: its slots keep them.
  addons = [{ code = "backup-slot", quantity = 3 }]
}

resource "masterdaweb_backup_schedule" "db" {
  instance_id = masterdaweb_instance.db.id
  days        = ["mon", "wed", "fri"]
  time        = "03:30"
  timezone    = "America/Sao_Paulo"
}

variable "subscription_id" {
  type = string
}
```

## Schema

### Required

- `days` (Set of String) The days it is backed up: sun, mon, tue, wed, thu, fri or sat.
- `instance_id` (String) The instance. Changing it moves the schedule to another instance.
- `time` (String) The time of day it is backed up, HH:MM (24h), in timezone.

### Optional

- `timezone` (String) The time zone of time, an IANA name like America/Sao_Paulo; UTC when left out.

### Read-Only

- `id` (String) The instance's id: an instance has one schedule.
- `last_run_at` (String) When it last made a backup (RFC 3339).

## Import

A schedule is imported by its instance's id:

```shell
# By the instance's id: an instance has one schedule.
terraform import masterdaweb_backup_schedule.db 4123
```
