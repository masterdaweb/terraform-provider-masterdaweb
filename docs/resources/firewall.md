# masterdaweb_firewall (Resource)

A firewall: rules evaluated in order, and default policies for what no rule matches, applied to the instances listed in instance_ids. Every change is committed onto exactly those instances, and Terraform waits for the commit to finish.

Rules apply in the order they are written, and the policies decide what no rule matches. Every change is staged
and then committed onto exactly the instances in `instance_ids` (one left out is detached); Terraform waits for
the commit. Rules made outside Terraform are removed on the next apply.

A rule gives either a `macro` (a named service: the `masterdaweb_firewall_macros` data source lists them) or a
protocol with its ports. `DROP` or `REJECT` as `policy_in` stops your own SSH too unless a rule lets it in.

## Example Usage

```terraform
resource "masterdaweb_firewall" "web" {
  name        = "web"
  description = "Web servers: HTTP(S) from anywhere, SSH from the office"
  policy_in   = "DROP"
  policy_out  = "ACCEPT"

  # Evaluated in this order.
  rules = [
    { direction = "in", action = "ACCEPT", macro = "SSH", source = "203.0.113.0/24", comment = "office" },
    { direction = "in", action = "ACCEPT", macro = "HTTP" },
    { direction = "in", action = "ACCEPT", macro = "HTTPS" },
    { direction = "in", action = "ACCEPT", protocol = "tcp", dest_port = "8000-8100", comment = "app ports" },
    { direction = "in", action = "ACCEPT", protocol = "icmp" },
  ]

  instance_ids = [masterdaweb_instance.web.id]
}
```

## Schema

### Required

- `name` (String) The firewall's name, up to 255 characters.

### Optional

- `description` (String) What the firewall is for, up to 500 characters.
- `enabled` (Boolean) Whether the firewall filters at all.
- `instance_ids` (Set of String) The instances the firewall protects: exactly these (one left out is detached).
- `policy_in` (String) What happens to inbound traffic no rule matches: ACCEPT, DROP or REJECT. DROP or REJECT also stop your own SSH unless a rule lets it in.
- `policy_out` (String) What happens to outbound traffic no rule matches: ACCEPT, DROP or REJECT.
- `rules` (Attributes List) The rules, evaluated in this order. Rules made outside Terraform are removed. (see [below for nested schema](#nestedatt--rules))
- `timeouts` (Attributes) How long Terraform waits, per operation, as a duration like "30m" or "1h". (see [below for nested schema](#nestedatt--timeouts))

### Read-Only

- `created_at` (String) When the firewall was created (RFC 3339).
- `has_pending_changes` (Boolean) Whether rules were changed outside Terraform without being committed.
- `id` (String) The firewall's id.

### Nested Schema for `rules`

Required:

- `action` (String) ACCEPT, DROP or REJECT.
- `direction` (String) in or out.

Optional:

- `comment` (String) A note on the rule, up to 500 characters.
- `dest_port` (String) Destination port, a range (8000:8100) or a comma-separated list, like 443. Needs protocol.
- `destination` (String) Where the traffic goes, in the same forms as source.
- `enabled` (Boolean) A disabled rule is kept but not applied.
- `macro` (String) A named service (HTTP, HTTPS, SSH…; the masterdaweb_firewall_macros list): it sets the protocol and ports.
- `protocol` (String) The protocol, lower-case as in /etc/protocols: tcp, udp, icmp… Only tcp, udp, sctp, dccp and udplite carry ports.
- `source` (String) Where the traffic comes from: an address, a CIDR, a FROM-TO range or a comma-separated list. Anywhere when left out.
- `source_port` (String) Source port, a range (1024:65535) or a comma-separated list. Needs protocol.


<a id="nestedatt--timeouts"></a>
### Nested Schema for `timeouts`

Optional:

- `create` (String) How long to wait for the first commit (default 10m).
- `update` (String) How long to wait for a commit (default 10m).

## Import

A firewall is imported by its id or by a name only it has:

```shell
# By id, or by a name only it has.
terraform import masterdaweb_firewall.web 0193f0e2-8c1d-7a7e-9b1e-2f6a4c0d9e11
terraform import masterdaweb_firewall.web web
```
