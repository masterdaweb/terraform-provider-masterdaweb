# masterdaweb_snapshot (Resource)

A snapshot of an instance, to restore it to this point, within the plan's snapshot quota. Snapshots expire 30 days after they are taken: one that expired is gone from the state, and the next apply takes it again. Restoring is done in the console or with the API (it deletes the snapshots newer than the one restored).

Snapshots count against the plan's snapshot quota and expire 30 days after they are taken. An expired snapshot
is gone from the state on the next refresh, and the next apply takes it again: to keep a recurring snapshot,
change its `name` (with the date, say). While another operation holds the instance (a backup, another
snapshot), Terraform waits for it, up to the timeouts.

## Example Usage

```terraform
resource "masterdaweb_snapshot" "before_upgrade" {
  instance_id = masterdaweb_instance.web.id
  name        = "before-upgrade"
  description = "Before the PHP 8.4 upgrade"
}
```

## Schema

### Required

- `instance_id` (String) The instance. Changing it takes a new snapshot.
- `name` (String) The snapshot's name: a letter, then 1 to 39 letters, digits, - or _, unique on the instance. Changing it takes a new snapshot.

### Optional

- `description` (String) A note on the snapshot, up to 255 characters. Changing it takes a new snapshot.
- `include_ram` (Boolean) Whether the memory is in the snapshot too (restoring brings the instance back running). Changing it takes a new snapshot.
- `timeouts` (Attributes) How long Terraform waits, per operation, as a duration like "30m" or "1h". (see [below for nested schema](#nestedatt--timeouts))

### Read-Only

- `created_at` (String) When the snapshot was taken (RFC 3339).
- `expires_at` (String) When the snapshot expires (RFC 3339), 30 days after it was taken.
- `id` (String) The snapshot's id.
