# masterdaweb_security_settings (Resource)

How the Security Center scans the account and who is told: one set per account. A setting left out is the account's own. Destroying this resource stops managing the settings; the account keeps them.

An account has one set of settings, so a configuration has one of these. Scanning is on by default; turning it
off stops new scans, and the score stops being refreshed. A new `default_frequency` applies to every instance
at once (one instance's own cadence is set in the console or with the API).

## Example Usage

```terraform
resource "masterdaweb_security_settings" "this" {
  enabled                = true
  default_frequency      = "weekly"
  notify_on_new_critical = true
  notify_on_score_drop   = false
}
```

## Schema

### Optional

- `default_frequency` (String) How often instances are scanned: weekly or monthly. A change applies to every instance at once.
- `enabled` (Boolean) Whether the account's instances and resources are scanned (on by default).
- `notify_on_new_critical` (Boolean) Whether a new critical finding is emailed.
- `notify_on_score_drop` (Boolean) Whether a drop of the security score is emailed.

### Read-Only

- `id` (String) Always security_settings.

## Import

```shell
# An account has one set of settings: any id imports them.
terraform import masterdaweb_security_settings.this security_settings
```
