# masterdaweb_vpn_user (Resource)

A login on a VPN gateway: a person who connects with the VPN app, with their own username and password. Every change is applied to the gateway in place right after it is saved (the gateway's other pending changes go with it); when applying needs a rebuild, the change stays saved and a warning says how to apply it.

## How changes reach the gateway

A VPN gateway keeps its logins in the platform's record and applies them on an *apply*, as the console's
Apply button does. This resource applies after each of its own changes — adding, changing or removing a
login — in place, and waits for the gateway (`timeouts`); the gateway's other pending changes go with it.
Several logins in one run are fine: an apply already running carries the next change too.

When applying needs a **rebuild** (an older gateway, or a setting like `route_all_traffic` changed and not
applied), a login never starts one — a few minutes offline, everyone disconnected. The change stays saved
and Terraform warns, saying so; apply it from the gateway's page in the console, or let
[`masterdaweb_vpn_gateway_settings`](vpn_gateway_settings) do it with `allow_rebuild = true`. A gateway that
fails to apply is a warning too: the login is saved, and `masterdaweb_vpn_gateway_settings` applies what is
waiting on its next run. A warning, not an error, because the login exists: an error would taint it, and
replacing it would lose a generated password.

## The password

Left out, the platform generates the password and Terraform keeps it in its state (which is sensitive): the
API shows it once, when the login is made. With `send_credentials = true` the person gets their username,
password and how to connect by email — when the login is made and when its credentials change. A password
in the configuration is set in place when it changes; after an import, it is set on the next apply.

## Example Usage

```terraform
# The gateway is an instance ordered from the VPN gateway image.
data "masterdaweb_vpn_gateway" "office" {
  name = "office-vpn"
}

# The platform generates the password and emails the person how to connect.
resource "masterdaweb_vpn_user" "maria" {
  gateway_id       = data.masterdaweb_vpn_gateway.office.id
  username         = "maria"
  email            = "maria@example.com"
  send_credentials = true
}

# A login whose password comes from a secret store, switched off for now.
resource "masterdaweb_vpn_user" "contractor" {
  gateway_id = data.masterdaweb_vpn_gateway.office.id
  username   = "acmecontractor"
  email      = "it@acme.example"
  password   = var.contractor_password
  status     = "inactive"
}

variable "contractor_password" {
  type      = string
  sensitive = true
}
```

## Schema

### Required

- `email` (String) The person's email, unique on the gateway: where send_credentials sends their access. Changed in place.
- `gateway_id` (String) The VPN gateway (masterdaweb_vpn_gateway). Changing it replaces the login.
- `username` (String) What the person signs in with: letters and digits, unique on the gateway. Changed in place.

### Optional

- `password` (String, Sensitive) The login's password, 8 to 128 characters. Left out, the platform generates one and it is kept here, in the state — the API shows it once and never again (not imported). Changing it sets a new one in place.
- `send_credentials` (Boolean) Whether the person is emailed their username, password and how to connect: when the login is made, and when its username, email or password changes.
- `status` (String) active, or inactive: the login is kept and refused. Changed in place.
- `timeouts` (Attributes) How long Terraform waits, per operation, as a duration like "30m" or "1h". (see [below for nested schema](#nestedatt--timeouts))

### Read-Only

- `created_at` (String) When the login was made (RFC 3339).
- `id` (String) The login's id.

## Import

A login is imported by its gateway's id and its own, without its password:

```shell
# By <gateway_id>/<login_id>. The password is not imported: the API never shows it.
terraform import masterdaweb_vpn_user.maria 0193f0e2-8c1d-7a7e-9b1e-2f6a4c0d9e11/0193f0e2-9d2e-7b8f-8c2f-3a7b5d1e0f22
```
