# masterdaweb_serverless_variable (Resource)

A service's environment variable. A secret is write-only: once saved, the API never shows its value again, so Terraform keeps the configured one. Each change starts a deployment unless deploy is false; removing a variable always does.

- A plain value is read back, so a change made elsewhere shows up in the next plan.
- A secret's value is never read back. Terraform keeps the configured value in its state and compares the
  variable's `version`: when it moved (the secret was changed elsewhere), the next plan sets the configured
  value again.
- A secret stays a secret: setting `secret` back to false replaces the variable.
- Creating a variable the service already has fails, so nothing set by hand is overwritten: import it instead.
- Variables a binding gives the service (`DATABASE_URL`, `MW_STORAGE_*`…) are the binding's, and `PORT`,
  `K_*` and `MW_*` are the platform's.

Each change starts a deployment unless `deploy = false`; removing a variable always starts one.

## Example Usage

```terraform
resource "masterdaweb_serverless_variable" "environment" {
  service_id = masterdaweb_serverless_service.web.id
  key        = "ASPNETCORE_ENVIRONMENT"
  value      = "Production"
}

# Write-only once saved: Terraform keeps the value it was given.
resource "masterdaweb_serverless_variable" "stripe" {
  service_id = masterdaweb_serverless_service.web.id
  key        = "STRIPE_SECRET_KEY"
  value      = var.stripe_secret_key
  secret     = true
}

# Given to the build too.
resource "masterdaweb_serverless_variable" "public_api" {
  service_id         = masterdaweb_serverless_service.web.id
  key                = "NEXT_PUBLIC_API_URL"
  value              = "https://api.example.com"
  available_at_build = true
}
```

## Schema

### Required

- `key` (String) The variable's name: letters, digits and underscores, not starting with a digit. `PORT`, `K_*` and `MW_*` are the platform's.
- `service_id` (String) The service the variable belongs to.
- `value` (String, Sensitive) The value. A secret's value is never read back: Terraform keeps the configured one.

### Optional

- `available_at_build` (Boolean) Whether the build gets it too (NEXT_PUBLIC_* and the like).
- `deploy` (Boolean) Whether setting or changing the variable starts a deployment. False saves it for the next deployment. Removing a variable always starts one.
- `secret` (Boolean) Whether the value is write-only once saved. A secret stays a secret: setting it back to false replaces the variable.

### Read-Only

- `id` (String) `<service_id>/<key>`.
- `updated_at` (String) When the variable last changed (RFC 3339).
- `version` (Number) Goes up each time the value changes. A secret changed elsewhere shows up as a change to apply.

## Import

A variable is imported as `<service_id>/<key>`:

```shell
# As <service_id>/<key>. A secret's value cannot be read: the next apply
# sets the configured one (nothing changes when it is the same).
terraform import masterdaweb_serverless_variable.environment 0193f0e2-9a4b-7c2d-8e1f-3a5b6c7d8e9f/ASPNETCORE_ENVIRONMENT
```
