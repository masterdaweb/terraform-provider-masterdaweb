# masterdaweb_security_findings (Data Source)

The Security Center's findings, riskiest first — severity, exploitability and exposure together —, across instances, serverless services, databases, buckets, access keys and the account. By default only what still counts (not resolved, not excepted); the filters narrow the list.

Reading it takes `security:read`.

## Example Usage

```terraform
data "masterdaweb_security_findings" "exploited" {
  severity = "critical"
}

output "actively_exploited" {
  value = [for f in data.masterdaweb_security_findings.exploited.findings : "${f.resource_name}: ${f.title}" if f.known_exploited]
}
```

## Schema

### Optional

- `category` (String) Only this category, like EXPOSED_SERVICE or VULNERABLE_SOFTWARE.
- `instance_id` (String) Only this instance's findings.
- `resource_id` (String) With a resource_type other than instance: only that resource.
- `resource_type` (String) Only this kind of resource: instance, serverless_service, database, bucket, storage_key or account.
- `search` (String) Only the findings with this text in their title, check id, address or resource name.
- `severity` (String) Only this severity: critical, high, medium, low or info.
- `status` (String) Only this status: open, resolved, excepted or false_positive. Every status but resolved and excepted when left out.

### Read-Only

- `findings` (Attributes List) The findings. (see [below for nested schema](#nestedatt--findings))
- `id` (String) Always security_findings.
