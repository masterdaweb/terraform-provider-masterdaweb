# masterdaweb_plans (Data Source)

The plans instances are ordered on (the plan of masterdaweb_instance), smallest first, with their rates per billing term. The filters narrow the list.

## Example Usage

```terraform
# The smallest plan with 2 vCPUs and 4 GB, billed monthly.
data "masterdaweb_plans" "medium" {
  term       = "MONTHLY"
  min_vcpus  = 2
  min_ram_mb = 4096
}

output "plan" {
  value = data.masterdaweb_plans.medium.plans[0].code
}
```

## Schema

### Optional

- `kind` (String) Only the plans of this kind, like VM.
- `min_disk_gb` (Number) Only the plans with at least this much disk included, in GB.
- `min_ram_mb` (Number) Only the plans with at least this much memory, in MB.
- `min_vcpus` (Number) Only the plans with at least this many vCPUs.
- `term` (String) Only the plans offered on this billing term: MONTHLY, QUARTERLY, SEMI_ANNUAL, ANNUAL or ON_DEMAND.

### Read-Only

- `id` (String) Always plans.
- `plans` (Attributes List) The plans: fewest vCPUs, then least memory and disk, first. (see [below for nested schema](#nestedatt--plans))

### Nested Schema for `plans`

Read-Only:

- `base_disk_gb` (Number) The disk it includes, in GB (more is ordered with main_disk_extra_gb).
- `code` (String) The plan's code (masterdaweb_instance.plan).
- `currency` (String) The rates' currency, like BRL.
- `description` (String) What it is for.
- `hourly_rates` (Map of String) Its rate per hour in micro-cents (millionths of a cent), by billing term; a term it is not offered on is left out.
- `kind` (String) What it provisions, like VM.
- `name` (String) Its name.
- `ram_mb` (Number) Its memory, in MB.
- `vcpus` (Number) Its vCPUs.
